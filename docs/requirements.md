# Requirements

## Personas
See the design spec, section 2.

## User stories

| ID | As a… | I want… | Acceptance criteria |
|---|---|---|---|
| US-01 | Store manager | yesterday's sales vs. target on my phone | The phone layout's first card shows Sales Value, Target and variance % for yesterday, for my store only |
| US-02 | Store manager | the fresh items most likely out of stock | A list of flagged perishable items for the last 7 days, sorted by estimated lost sales |
| US-03 | Store manager | footfall and basket vs. last year | Receipts and Basket Value with YoY % for the selected period |
| US-04 | Regional manager | my stores ranked by like-for-like growth | A sorted bar of LFL Growth % for the stores in my region only; non-LFL stores are excluded and labelled |
| US-05 | Regional manager | to know if a store's growth comes from shoppers or baskets | LFL Footfall Growth % and LFL Basket Growth % per store; together they reproduce LFL Growth % |
| US-06 | Regional manager | to drill from a store to its detail | A drill-through to a Store detail page that keeps the period filter |
| US-07 | Category manager | promotion uplift by family and the post-promotion dip | Promo Uplift % and Post-promo Dip % by family, with the top promotions table |
| US-08 | Category manager | margin by family | Gross Margin % by family; hidden from the Store operations role |
| US-09 | Head office | network vs. target by region with last year | Sales vs Target % and YoY % by region on the Network overview |
| US-10 | Every user | to see only what I am allowed to | The RLS/OLS test matrix passes for all four test users |

## Non-functional
- Every visual's query < 500 ms warm on full data (see `performance.md`).
- WCAG AA contrast; colour never the only signal; alt text on every visual.

## Synthetic columns
`item_price.unit_price`, `item_price.unit_cost`, `sales_target_month.target_value` (and the daily
allocation), `weekday_weight.weight`, `state_region.region_id`, `store_profile.selling_area_m2` —
generated by `retail_pipeline erp-seed` with seed 42; rules are in design spec section 4.2.
`user_access.*` rows for the two store-operations test users are generated by
`retail_pipeline erp-seed --upn-domain <tenant domain>` (see `docs/security.md`).
